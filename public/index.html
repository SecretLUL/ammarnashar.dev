What all three have in common

  • No account
  • No tracking
  • One file
  • Updates itself
  • Open source

Just download it

One file. No installer wizard, no account, no "sign up to continue". {{winmedic.name}} is a single .exe (or one winget command), and {{mcperfbooster.name}} doesn't even need .NET installed.

Your stuff stays yours

No tracking, no telemetry. {{sotto.name}} can transcribe completely offline, and {{winmedic.name}} only goes online for updates, connection checks and clean system files during a repair.

Safe to try

{{winmedic.name}} sets a restore point before it touches anything. {{sotto.name}} warns you before a recording gets overwritten. {{mcperfbooster.name}} clears out old mod versions so nothing crashes.

Always up to date

All three check GitHub for new versions and update in one click. Every update gets checked against its SHA-256 first.

Open source

Everything's on GitHub: {{winmedic.name}} under GPL-3.0, {{sotto.name}} and {{mcperfbooster.name}} under MIT. Read the code, fork it, break it, send a fix.

How I work

Software engineer on paper, Senior Vibe Coder on GitHub. The honest split: AI does a lot of the typing, I do the thinking, the reviewing and the testing on real PCs.

  1. 01

    Think first.

    Before I write any code, I figure out the data, the edge cases and the stuff that must never break. That's where good software actually gets decided.

  2. 02

    Build fast.

    AI models like Claude and Gemini take care of the boring parts and the boilerplate. That keeps the loop from idea to working build really short.

  3. 03

    Trust nothing.

    AI code gets reviewed like a stranger's pull request: race conditions, memory safety, compiler warnings. Then it has to survive real hardware. {{winmedic.name}}'s checks, for example, are tested against output from real Windows installs.
